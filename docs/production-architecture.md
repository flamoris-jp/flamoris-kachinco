## Foundation rationale (historical implementation scope)

## Goals and non-goals

Human-first Windows editing, with AI as a first-class caller of the same editing
API. An independent C# product, with no dependency on Cutwork or FLAMORIS-2D.
The foundation registers MOV/WAV metadata, edits and inspects timelines, saves
and reopens projects, and evaluates deterministic render plans. It does not
decode, play, render full images, encode, run Python, or start an MCP server.
Clapper → Recipe → Clip remains the signature future workflow, not an implicit
promise of functionality in this milestone.

## Runtime and physical boundaries

Decision: .NET 10 LTS + WPF. Windows is the explicit initial target; WPF provides
maintainable desktop controls, dialogs, DPI/layout and native interop without a
browser runtime. WPF owns presentation only; a future compositor can supply a
bitmap/GPU surface without making WPF rendering the export authority.
See [Microsoft's .NET 10 announcement](https://devblogs.microsoft.com/dotnet/announcing-dotnet-10/)
and [WPF overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/).

| Project | Responsibility | Dependencies |
| --- | --- | --- |
| `product/Kachinco.Core` | Immutable domain, time, validation, command/session/query, evaluation | BCL only |
| `product/Kachinco.Infrastructure` | Versioned JSON/file persistence, render/export contracts and FFmpeg boundary | Core |
| `product/Kachinco.App` | WPF shell, transient selection and file dialogs | Core, Infrastructure |
| `test/Kachinco.Tests` | Headless contract and integration regression suite | Core, Infrastructure |

No speculative empty plugin/media/MCP projects. Add adapters when their behavior
exists. Runtime never references tests, staging or history.

## Domain and identity

Project is persistent authority: ID, name, assets, sequences. Each sequence owns
settings, explicit duration and ordered tracks. Track kinds are Video, Audio,
Subtitle. Media assets are source registrations, separate from clip instances;
one source can be used repeatedly. Captions are first-class items with ID, start,
duration and text, rather than SRT text or transient UI overlays.

All entity IDs are nonempty UUIDs, unique across the whole project, including
captions. Callers supply IDs in commands, so AI can reference newly created items
within a batch. New IDs may be generated by adapters; replay uses recorded IDs.
Names and filesystem paths are never identity. Split retains the left ID and
requires a new right ID. Undo/redo retains both identities.

Domain records and ImmutableArray collections are snapshots. The session alone
owns the current committed snapshot. Queries cannot mutate it. Selection,
playhead, zoom, open filename, history, revisions, export jobs and caches are
transient. Project replacement clears history and increments session revision.

## Canonical time

Decision: **35,280,000 integer ticks/second**, shared by video, audio and captions.
This represents 44.1/48 kHz sample boundaries and common integer/1001 FPS
frame boundaries exactly, unlike simply copying 2D's 120,000 ticks/second.
Other sample rates use the same rounded conversion, not a separate clock.
FPS is a reduced positive integer numerator/denominator, never a double.
Conversions use BigInteger intermediates and round-half-up for nonnegative times;
overflow is rejected. No accumulated frame-step rounding: frame n is independently
converted from n × ticksPerSecond × fpsDenominator / fpsNumerator.

All ranges are half-open [start,end); sourceIn is inclusive, sourceOut is derived
as sourceIn + duration and exclusive. Initial playback rate is exactly 1.
No negative time, zero-duration items or arithmetic overflow is accepted.
Sequence duration is explicit; commands cannot silently extend it. Clips/captions
must fit it. Trim explicitly supplies the new timeline start, sourceIn, duration;
it never guesses whether the caller intended a slip or edge trim.
Export includes exactly the frame indices whose rounded tick is < duration.
Frame count uses the same rounding boundary, including non-frame-aligned durations.
Presentation may use seconds; domain mutations still supply integer ticks.

## Editing and diagnostics

`EditorSession.Execute(EditBatch)` is the sole mutation path for UI, scripts and
future MCP. Typed command records cover project/sequence creation, MOV/WAV
registration, tracks, insert/move/trim/split/delete, track order, clip appearance,
audio gain/mute and captions. No arbitrary property paths or reflection setter API.

A batch runs against an immutable candidate, validates after every command, then
commits once. Failure leaves project, revision, Undo and Redo unchanged. One batch
is one Undo step. No filesystem side effects occur in commands. Each request has
an optional expected revision; stale AI decisions receive REVISION_CONFLICT.
Dry-run executes the same path without history/state changes. This is optimistic
concurrency, not an idempotency service: a lost response should be followed by a
query. Session methods serialize access. Successful undo/redo increment revision;
new edits clear Redo. History is bounded to 100 snapshots by default.

Results contain success, revision, and diagnostics with code/severity/message/
entityId/path. Codes are machine authority; UI may localize explanations. Missing
IDs, duplicate IDs, invalid settings/ranges, track/media mismatch, unsupported
formats and invalid properties fail structurally. Query ordering is explicit:
assets/sequences by ID; tracks bottom-to-top in stored order; clips and captions
by timeline start then ordinal UUID. Overlapping clips are allowed and composite
in that deterministic order. Audio overlaps mix; video MOV audio is not implicitly
enabled. Dedicated WAV clips provide the initial audio path.

Core MOV/WAV registration accepts explicit caller metadata and remains free of file
and process IO. Phase 1 human import obtains that metadata through Infrastructure's
`IMediaProbe`/`FfprobeMediaProbe`: argument-list process construction, bounded JSON
and stderr reads, cancellation, structured failures, and one canonical decimal
seconds → `TimelineTime` conversion. Probe success produces an ordinary
`RegisterMedia`; no Project mutation occurs before that command validates.

References are absolute local paths or project-relative paths, not remote URLs.
Opening a project never fails merely because referenced media is absent. The media
resolver resolves relative paths against the `.fkproj` directory and emits
`MEDIA_MISSING`/`MEDIA_REFERENCE_UNRESOLVED` warnings keyed by `mediaAssetId`.
Relink probes first and emits `RelinkMedia` only when kind and all existing source
ranges remain compatible. It changes path/technical metadata on the existing asset,
preserving asset and clip identities and timeline placement through Undo/Redo.

MOV embedded audio remains probe metadata only in Phase 1. It is not silently
turned into an independently editable audio clip; dedicated WAV remains the audio
timeline source until an explicit domain contract changes that behavior.

## Phase 1 timeline authoring projection

The WPF shell now has a native menu, a separate toolbar, media bin, inspector and
a multi-track timeline with fixed headers, ruler, horizontal/vertical scrolling,
zoom, playhead and V/A/S presentation labels. Stable `trackId` remains authority;
labels are never used to address edits. Selection, scroll, zoom, drag preview,
snapping and playhead remain transient WPF state.

`TimelineViewport` maps canonical ticks to decimal pixels and maps pointer deltas
back with one explicit round-half-away-from-zero operation. Dragging always starts
from the committed clip range, so successive pointer events cannot accumulate
domain drift. `TimelineSnapping` compares integer tick distances against sequence
start, other clip edges and playhead, resolving ties toward the lower tick. Gestures
produce typed move/trim commands through `TimelineEditPlanner`; split uses an
explicit tick and caller-generated right ID. The WPF surface raises command intent
and never writes a Project record.

Playback-shaped toolbar controls are disabled and labelled for Phase 2. Phase 1
does not create a timer, decoder, UI-only playback cursor, audio engine or alternate
clock. The transient edit cursor is only an explicit authoring position.

## Persistence v1

`ProjectJson` maps to explicit version-specific DTOs, not direct domain graph
serialization. Envelope: format `flamoris-kachinco`, schemaVersion 1, timebase,
project. `.fkproj` is UTF-8 JSON and references external media; it is not a media
bundle. Tick fields are decimal strings to avoid JavaScript 53-bit precision loss.
UUIDs are strings, enums named strings. Arrays and required fields are explicit.
See `project-format-v1.md` for the complete field contract.

Envelope/version dispatch precedes payload decoding. Unknown versions are rejected
with SCHEMA_UNSUPPORTED; unknown v1 fields are rejected to prevent silent data loss.
No historical version exists yet: add a pure, tested version-to-version migration
before admitting one. Validate before serialization and before returning a loaded
project. Malformed JSON, nulls, duplicate properties and invalid domain states are
diagnosed. File service bounds input size, writes a sibling temporary file, flushes,
then replaces the destination; failed writes must preserve an existing project.
Loading returns a candidate; only successful session replacement changes the editor.

## Evaluation, compositor and audio

`TimelineEvaluator` produces an immutable `EvaluatedFrame` for an explicit sequence
and tick. It uses the same active-range and source mapping rules for every caller.
Frame contains ordered video layers, audio contributions and caption entries;
disabled tracks/items contribute nothing. Video layers carry source tick, transform,
opacity and blend mode. Audio carries source tick and effective gain.

Canvas coordinates: output pixels, top-left origin, +x right, +y down. Transform
uses translation, clockwise degrees, positive x/y scale around source origin;
resampling/fit policy belongs to the future renderer and must be fixed before
image-level parity can be claimed. Normal and Screen are the implemented blend
contract. A small straight-alpha normalized RGB reference calculation fixes their
alpha/opacity behavior; it is not a production image renderer. Initial RGB values
are encoded SDR sRGB; linear/HDR/color management requires an explicit new contract.
Future masks/effects add typed evaluated inputs, not UI-only blend switches.

`IFrameRenderer` consumes EvaluatedFrame and returns owned packed RGBA8 output;
both Preview and Export must call it. `IAudioRenderer` consumes the same sequence
snapshot and shared audio-range plan, producing interleaved float32 PCM sample
blocks. Audio uses sample-index-to-tick conversion, not video-frame stepping.
No real renderer/decoder/mixer is claimed by this foundation.

## Export and FFmpeg

Production flow: immutable project snapshot → shared evaluation → shared compositor
+ audio mix → rendered RGBA frames + PCM → FFmpeg encoding/mux → final file.
`ExportPlanner` provides lazy frame access, frame count, FPS, size and audio timing.
No UI screen capture and no second FFmpeg filtergraph timeline evaluator.

`IExportService` owns job orchestration, snapshot/revision, progress, cancellation
and diagnostics. `IVideoEncodingBackend` is the handoff after rendering. The
FFmpeg adapter receives a rendered media stream and explicit executable settings;
it must not know clip placement or mutate Project. This milestone intentionally
returns EXPORT_NOT_IMPLEMENTED instead of simulating success or producing a file.

Planned initial preset: MP4 + H.264/yuv420p + AAC, common YouTube-compatible SDR
delivery for both sequence presets; transparency is flattened by the compositor.
Frame rate remains rational. PCM sample count and final partial frame padding
must be coordinated in the production exporter, without changing sequence meaning.
Progress counts completed frames/samples, cancellation reaches renderer, audio and
FFmpeg and kills/disposes child processes, incomplete output uses a temporary file.

FFmpeg executable configuration is application state: explicit configured path
first, then PATH discovery; report FFMPEG_NOT_FOUND and version/capability problems.
No executable downloads, shell interpolation, CLI construction in WPF, or custom
encoder. Future backend uses ProcessStartInfo.ArgumentList, drains stderr, and maps
exit/error state to structured diagnostics. Distribution/license review belongs to
the milestone that actually bundles FFmpeg; none is bundled here.

## AI/MCP surface and extensions

The live stdio bridge attaches to the same WPF EditorSession through a local-only
Windows named pipe through Flamoris.Mcp.Core 1.1.0. ADR 0005 and `api-contract.md` own the current capability,
permission/discovery and version contracts. Stop, permission changes, Open/New
and shutdown revoke before further access. Ordinary edits/history remain typed
and revision-qualified; there is no second Project, timebase or MCP editor.
File-capable external tools fail closed until separately authorized; UI import,
Recipe generation and export remain the production file workflow. Read-only
Recipe validation is a cancellable bounded compiler, not arbitrary execution.

Clappers will be sequence-owned persistent anchors with domain geometry and
referential validation. Recipes require versioned provenance, input IDs and seeds;
they enter as normal media + clip commands in one batch. They require a schema
change, not silently discarded unknown JSON fields. No Python worker or speculative
Recipe object is introduced now. Kinetai/AudioAnalyzer are future adapters supplying
ordinary assets/metadata/commands. No separate integration-owned timeline.
